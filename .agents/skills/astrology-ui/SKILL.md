# Western astrology website UI

1. Read PRD and design directions; modes share one account/chart. Treat visual concepts as alternatives pending approval. Use ui-ux-pro-max searches only where relevant and assess fit.
2. Distinguish outer signs, inner houses, planetary glyphs, ASC/MC, longitudes, retrograde and aspect lines. Draw from engine data; do not recalculate astrology in rendering.
3. Assess SVG versus Canvas. Favor inspectable SVG for a modest chart, paired with a semantic text table. Use synthetic fixtures for mockups.
4. Support hover/click, keyboard/touch selection, labeled zoom/reset and scroll while zoomed. Do not rely on color, hover or tiny glyphs alone. Unknown time removes unsupported angles/houses with an explanation.
5. Define typography/contrast/spacing/error/partial/Mock states and reduced motion; review desktop/laptop/tablet/phone sizes. Public SEO and private chart layouts remain separate.
6. Keep Premium/forecast tools outside MVP. Prototypes are review artifacts, not deployed apps or certified calculations.

Acceptance: readable chart and data alternative, visible frame/house system, stable fact IDs, three distinguishable concepts when requested, no production implementation before design approval.
